## 已定（2026-11-04）

| 决定 | 原因 |
|---|---|
| 放弃 Electron 版 tandem，用 Tauri 重新写 | 目标是更低内存和更快启动。实测见 [measurements](measurements/2026-11-04-startup-and-memory.md) |
| 项目名为 Tandem，沿用原有图标 | 用户决定 |
| 只复刻界面，不是 fork，不跟进 Cindy 上游 | 重写后上游合并已无意义 |
| 界面尽量复刻 Cindy，品牌素材除外 | 用户决定。名称、Logo、角色形象不在许可范围内 |
| 任务数据走原生会话 | 沿用 loom 的方向。原生方案本身的问题（单写入者、外部状态）会留下，要在这里解决 |
| 不双写：不维护自己的会话记录，读取时把原生格式转成界面格式 | 存两份就要处理同步、回退分支和终端续聊带来的不一致。只认 CLI 的文件，从终端续聊和删掉 Tandem 都不会丢东西，实测读取也够快 |
| 本地只存可以丢弃的数据：界面状态（置顶、别名），以及需要时可重建的索引 | 这些内容 CLI 不保存，丢了也不影响任务 |
| 删除旧 fork 的 GitHub 仓库，新仓库用 `mingzaily/tandem` | 用户决定。旧版不再使用，Cindy 的代码可以从上游取得 |
| 手机端用 PWA，加自建中转，部署到用户的腾讯云服务器 | 官方 App 依赖 Cindy 账号和协议，而且 iOS 自建 App 需要付费开发者账号 |
| 仓库顶层分 `docs`、`desktop`、`pwa`、`relay` | 用户决定 |
| 所有规范放在 `docs/` | 用户决定 |
| "本任务都允许"只存内存，不写 CLI 设置 | CLI 建议把规则写进项目的设置文件，这会改用户的配置。每轮是新进程，所以规则放在内存里，下一轮用 `--allowedTools` 传回。Tandem 退出后失效 |
| 重命名、置顶和归档存在 Tandem，不写 CLI 的任务文件 | 写进任务文件可能和正在运行的 CLI 冲突。代价是终端里看不到这些改动 |
| 只显示分支，不切换 | 切换分支可能打乱工作区里的改动，要隔离就用 worktree |
| worktree 交给 CLI 的 `--worktree` 创建 | 不用自己维护 Git 操作。任务按原项目分组，行尾加标记 |
| 读当前分支直接读 `.git/HEAD`，不运行 `git` | 在项目里运行 `git` 可能触发它配置的外部程序，而这里只需要一个名字 |
| Codex 读取和运行都走 `codex app-server` | 旧任务文件是压缩的，分叉要拼父任务，官方接口都处理好了。读取用一个空闲 60 秒就退出的进程，运行每轮一个进程，结束就退出，否则写入锁放不掉 |
| Codex 线程固定以 `read-only` 启动，权限放在 `turn/start` | 启动时带可写沙箱，或用户配置默认可写，`app-server` 会把目录写进 `config.toml` 的信任列表。这样才不改用户配置 |
| Token 取一次快照后归本仓库维护 | Cindy 的生成器绑定了它的桌面端路径 |
| 放弃 loom 的 Git 历史，只保留文档 | 用户决定。文档用来记录思考过程，历史本身不再需要 |
| Cindy 和 ccgui 的代码放在 `docs/reference/repos/`，不上传 | 实现时要查阅，但不属于这个项目。新仓库因此不带旧历史 |
| 中转协议端到端加密，桌面端和手机都主动连中转 | 中转部署在公网，任务内容和审批不能经过它的明文。配对确认走系统对话框。手机可以选完全访问，用户决定 |
