## 已定（2026-11-04）

| 决定 | 原因 |
|---|---|
| 放弃 Electron 版 tandem，用 Tauri 重新写 | 目标是更低内存和更快启动。实测见 [measurements](measurements/2026-11-04-startup-and-memory.md) |
| 项目名为 Tandem，沿用原有图标 | 用户决定 |
| 只复刻界面，不是 fork，不跟进 Cindy 上游 | 重写后上游合并已无意义 |
| 界面尽量复刻 Cindy，品牌素材除外 | 用户决定。名称、Logo、角色形象不在许可范围内 |
| 任务数据走原生会话 | 沿用 loom 的方向。原生方案本身的问题（单写入者、外部状态）会留下，要在这里解决 |
| 不双写：不维护自己的会话记录，读取时把原生格式转成界面格式 | 存两份就要处理同步、回退分支和终端续聊带来的不一致。只认 CLI 的文件，从终端续聊和删掉 Tandem 都不会丢东西，实测读取也够快 |
| 本地只存可以丢弃的数据：界面状态（置顶、别名），以及需要时可重建的索引 | 这些内容 CLI 不保存，丢了也不影响任务 |
| 删除旧 fork 的 GitHub 仓库，新仓库用 `mingzaily/tandem` | 用户决定。旧版不再使用，Cindy 的代码可以从上游取得 |
| 手机端用 PWA，加自建中转，部署到用户的腾讯云服务器 | 官方 App 依赖 Cindy 账号和协议，而且 iOS 自建 App 需要付费开发者账号 |
| 只支持 macOS，不适配 Windows，CI 也不构建 | 用户决定 |
| 仓库顶层分 `docs`、`desktop`、`pwa`、`relay`、`site` | 用户决定。`site` 是文档站，以后也做产品官网，`docs` 只放内部文档 |
| 所有规范放在 `docs/` | 用户决定 |
| "本任务都允许"只存内存，不写 CLI 设置 | CLI 建议把规则写进项目的设置文件，这会改用户的配置。每轮是新进程，所以规则放在内存里，下一轮用 `--allowedTools` 传回。Tandem 退出后失效 |
| 重命名、置顶和归档存在 Tandem，不写 CLI 的任务文件 | 写进任务文件可能和正在运行的 CLI 冲突。代价是终端里看不到这些改动 |
| 只显示分支，不切换 | 切换分支可能打乱工作区里的改动，要隔离就用 worktree |
| worktree 交给 CLI 的 `--worktree` 创建 | 不用自己维护 Git 操作。任务按原项目分组，行尾加标记 |
| 读当前分支直接读 `.git/HEAD`，不运行 `git` | 在项目里运行 `git` 可能触发它配置的外部程序，而这里只需要一个名字 |
| Codex 读取和运行都走 `codex app-server` | 旧任务文件是压缩的，分叉要拼父任务，官方接口都处理好了。读取用一个空闲 60 秒就退出的进程，运行每轮一个进程，结束就退出，否则写入锁放不掉 |
| Codex 线程固定以 `read-only` 启动，权限放在 `turn/start` | 启动时带可写沙箱，或用户配置默认可写，`app-server` 会把目录写进 `config.toml` 的信任列表。这样才不改用户配置 |
| Token 取一次快照后归本仓库维护 | Cindy 的生成器绑定了它的桌面端路径 |
| 放弃 loom 的 Git 历史，只保留文档 | 用户决定。文档用来记录思考过程，历史本身不再需要 |
| Cindy 和 ccgui 的代码放在 `docs/reference/repos/`，不上传 | 实现时要查阅，但不属于这个项目。新仓库因此不带旧历史 |
| 中转协议端到端加密，桌面端和手机都主动连中转 | 中转部署在公网，任务内容和审批不能经过它的明文。配对确认走系统对话框。手机可以选完全访问，用户决定 |

## 已定（2026-11-05）

| 决定 | 原因 |
|---|---|
| 待发送队列由 Tandem 的 Rust 后端管理，按任务保存在 `~/.tandem/queues/` | 进入 CLI 自带队列后无法排序和删除。未发送消息是可丢弃草稿，原生任务文件仍是已发送内容的唯一来源 |
| 正常结束后逐条发送，停止、出错和应用重启后暂停，用户点“继续发送”恢复 | 明确发送边界，保留用户对停止和恢复的控制 |
| 排队消息携带附件和入队时的模型、强度、权限选项 | 草稿附件原本只在内存中，入队落盘后由队列接管生命周期；后续输入框设置只影响新入队的消息 |
| 队列面板照 Cindy 的几何和 token 实现，用指针事件和键盘排序 | Tauri 窗口会拦截 HTML5 文件拖放，项目侧栏已有可复用的指针交互方式。插话只预留操作位置，手机端协议本次保持原样 |
| 生成标题使用独立模型请求，通过各 CLI 的原生改名接口保存 | 用户要求聊天记录保持原样，同时让终端和其他客户端读到标题。手动重命名仍是本地别名；原生保存成功后清除原别名，生成期间的新手动别名保留 |
| 远程配对等待中转准入确认，再展示配对码或交付长期令牌；重连时先恢复全部长期哈希 | 用户批准桌面端接入 `allow-ack` 与 `disconnect`。确认对应实际登记和落盘，重登记可恢复丢失的中转准入文件 |
| 配对使用相对期限，运行时长使用单调时钟 | 两端系统时钟差不参与配对期限和运行用时计算；快照保留原始开始时间和已运行时长 |

| 文件变更展示对照 Cindy 的 TurnChangesCard，跟随每轮结果保留在消息流中 | 输入区上方的摘要浮层与队列层次混杂，右对齐也造成明显偏移。使用原版已有的卡片结构、几何和 token，默认展示 3 个文件；输入区集中处理待发送内容 |
| 文件变更卡片继续使用原生工具记录的只读派生数据 | Tandem 已有工具记录可以重建文件清单与可信行数；完整差异和撤销需要独立的数据与行为契约 |
| 队列保留 Cindy 无标题栏骨架，按 review 确认密度和对齐适配 | 32px 行、18px 缩略图、上下各 6px；后续按把手间距反馈将队列、折叠与输入正文统一到 24px。进入队列区全体操作浅显，固定占位；折叠作为末行。Rust 队列与指针、键盘排序沿用原流程 |
| 运行与暂停状态共用输入卡片上方一行 | 用户要求状态始终位于整张卡片上方。共用 32px 状态行，运行时右侧耗时/Token，暂停时右侧“继续发送”；暂停使用轻量 Pause 图标。图标与文字直接居中，移除原版向上 1px 的图标偏移 |
| 模型配置提交后立即更新发送偏好 | 核对 Cindy 完整链路后移除二次确认，保留恢复默认与手势取消；Tandem 继续使用单份发送偏好，已排队消息保留原快照 |
| 生成标题仅保留任务菜单入口，标题栏补 CLI 图标 | 用户要求 CLI 类型用图标表达，通过悬停说明类型。用 CaseSensitive 区分标题生成、ShieldCheck 区分自动审批；Sparkles 保留思考与运行状态含义 |
| 队列领取先持久化发送中记录，CLI 接收确认后删除；重启恢复到队首并暂停 | 进程启动与接收提示词是两个边界。崩溃时可能缺少接收结果，保留草稿与证据，由用户核对后决定是否重发。单个坏队列独立保留为 `.corrupt`，健康任务继续工作 |
| 外部写入者覆盖只授权一次发送尝试，队列文件省略该标记 | 后续条目、失败恢复和应用重启重新检查写入者，尊重用户当时允许继续发送的范围 |
| 队列图片独立保存，JSON 只保存引用，空队列删除文件 | 20 张 5MiB 图片的内联 JSON 达 133.34MiB，编辑与排序约 251/255ms；独立图片后约 3/3ms，加载后新建页常驻内存从约 750MiB 回到约 82MiB，见最终 review 性能记录 |
| 确认卡片等待后端确认后结束，失败保留回答并允许重试 | 用户回答必须可恢复；其他调用先回答时由后端 `requestSettled` 结束过期卡片。桌面错误分类与手机现有协议分别保持各自契约 |
| Tandem 自有持久化统一到 `~/.tandem/`，配置归 Rust，页面保留内存快照 | 用户确认。`config.toml` 可手改并保留注释，界面状态与手机密钥分文件保存；CLI 自己的配置和会话保持其原有位置。缓存只放可重建数据，按需创建 |
