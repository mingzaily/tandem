# 设计规则

> **状态**：权威
> **读取时机**：新增或修改界面、组件、布局、样式、动效或文案之前

Tandem 的目标是**尽量复刻 Cindy 的界面**。`upstream/` 是原样复制的规范，本文件说明它在 Tandem 里怎么用，两者冲突时以本文件为准。

主题名称统一采用主题清单的原名（如 Plain、Atom One Light、Solarized Light），在各语言界面保持一致；显示模式、字段标签和说明按界面语言翻译。

## 复刻方法

1. 先在原版代码里找到对应组件，照搬它的几何、token、字号和交互，不要凭规范文字猜。
2. 原版代码在 `docs/reference/repos/cindy/apps/desktop/src/renderer/`。这份仓库不上传，新机器上的取法见 [参考资料](../reference/README.md)。
3. 改完要看实际截图，不能只看代码。

## 手机端

PWA 复用桌面端 token、14px/medium 任务标题、消息与工作组的层级，保留手机的安全区、VisualViewport 键盘布局和底部选择面板。续聊输入卡最小 112px，新建最小 140px，圆角 12px，正文内距使用 `--composer-content-inset`，手机端覆盖为 24px；输入使用 16px 防止 iOS 聚焦缩放，自动增高至 240px。发送按钮视觉直径 28px，触控区域扩至 44px。

工作组沿用桌面端的“正在处理 / 已工作 / 已处理”层级、最近 5 条活动预览和逐段完成状态；尚无最终回复、以工作记录结尾的历史轮次默认展开外组并用“工作过程 · 记录时长”，恢复的缺结果工具保持静态，进度正文直接可见。手动收起只保留组头，再次展开显示全部，继续输出时保持用户选择。超过 80 条的展开清单使用 420px 虚拟滚动区域。任务的展开状态、模型与强度选择、未发送文字保存在页面内存；新建默认按 CLI 独立保存。本轮失败在所属轮次末尾使用中性底色和错误图标，简短原因直接可见，长技术详情折叠；输入框上方继续显示加载、保存等当前操作错误。权限确认和提问卡位于输入卡上方、间距 10px，保留同一输入框、草稿与停止入口；长卡片独立滚动。回答提交期间禁用重复操作，成功等待已处理事件移除卡片，失败保留回答并在卡片内显示原因。模型、强度、权限面板的选中行保留底色与勾选，展开时入口保持按下反馈。

## 工具名称与详情

运行行沿用 Cindy 的“工具名 运行中…”；长名称单行省略，悬停查看全名。等待确认优先，工具结束后切换到当前的思考或回复状态；并行工具乱序完成时显示仍在运行的调用。行高、图标、活动呼吸和右侧耗时/Token 沿用共用状态行。

工作记录里的 MCP 主行按 `toolUseDescriptor.ts`、`actionPresentation.ts` 和 `AgentActionRow.tsx` 显示“调用 服务器 · 可读工具名”。服务器标识保持原值，工具部分的下划线转空格，主文字 14px/medium。参数摘要进入悬停说明，原始输入和结果通过展开查看。通用未知工具主行保留原名，参数从详情读取。

## 不复刻的内容

Cindy 的名称、Logo、角色形象和宣传图不在 Apache-2.0 许可范围内。应用图标用 [`docs/brand/tandem-icon.svg`](../brand/tandem-icon.svg)，标记用 `tandem-mark.svg`。

菜单栏使用 [`tandem-tray.svg`](../brand/tandem-tray.svg) 生成的 `desktop/src-tauri/icons/tray-template.png`：44×36 像素的横向透明画布，对应菜单栏的 22×18pt 显示尺寸，双环实际高度约 13pt、宽度约 20pt。只有双环为不透明区域，交叉处保留加宽的透明留缝。macOS 按模板图标的透明通道着色，跟随菜单栏外观和选中状态。更新源文件后，在 macOS 的仓库根目录生成 PNG；Tauri 先等比居中生成方形图，再裁掉上下的透明留白：


## Token

- `desktop/design/tokens/tokens.css`：字号、间距、圆角、动效等基础 token。
- `desktop/design/tokens/colors.css`：基础颜色。浅色写在 `:root`，深色写在 `.dark`。
- `desktop/design/tokens/theme.css`：覆盖 `colors.css` 的暖色主题值，界面实际看到的颜色以它为准。
- `desktop/design/tokens/tailwind.generated.ts`：Tailwind 的字号、间距、圆角和字重映射。

这些文件已归本仓库维护，要改 token 就直接改，并同时改好浅色和深色。来源见 `SOURCE.md`。

写法规则，由 `desktop/src/lib/designTokens.test.ts` 检查：

- 颜色和动效一律用 token，不写裸值。
- 只能引用存在的 token。
- 部分 token 存的是 HSL 三元组（如 `--sidebar`），要写成 `hsl(var(--sidebar))`。直接写 `var(--sidebar)` 是非法颜色，边框会退成黑色。
- 菜单和配置浮层使用 `--shadow-menu`，Tailwind 写为 `shadow-[shadow:var(--shadow-menu)]`。带类型提示才能生成 box-shadow，普通 `shadow-[var(...)]` 会被解释成颜色。

## 指针与交互反馈

模型列表中，选择按钮与配置按钮是同一列表条目的平级控件。选择按钮表达选中状态；方向键左键和右键保留配置入口，Esc 关闭配置后焦点回到发起控件。

确认卡片提交期间保留并禁用操作。失败后显示原因、恢复操作并保留用户输入；成功或请求已结束时移除卡片。

按钮、链接、可选择项和开关使用手形；文字输入使用 I 形；拖动把手使用 grab/grabbing；强度滑块使用水平调整指针；禁用控件使用普通箭头。悬停与按下沿用各组件的表面色和文字色变化，键盘操作保留可见焦点环。

桌面端的悬停说明统一交给 `TooltipLayer.tsx`，控件使用 `data-tooltip`，`Tip` 作为语义包装复用同一层。指针停留或键盘聚焦 1000ms 后显示；移动到另一个控件重新计时，离开、点击、滚动、Esc 或窗口失焦时关闭。提示通过 Portal 放到页面最上层，超出底边时改向上显示。可选的 `data-tooltip-tags` 使用 JSON 字符串数组传入底部标签，正文和标签均按纯文本渲染；标签变化同步更新已打开的提示，空标签保持普通提示样式。保留控件的可访问名称，并在提示出现时建立 `aria-describedby`；原生 `title` 留作组件入参时由基础控件转换为 `data-tooltip`。

任务排序和右侧相对时间共用最近活动时间：新输入成功入队、轮次开始、插话被接受及轮次结束（含失败、停止）时立即推进内存时间，持续输出的每个字符保持列表原位。原生扫描继续提供标题与路径，时间取本次已观察活动和原生更新时间中的较新值，旧扫描返回后保持新顺序。外部任务跟随读取时使用原生消息的真实时间；打开查看本身保持活动时间不变。内存时间索引随应用退出清理，重启后以 CLI 原生记录为准。相对时间复用应用已有分钟时钟，窗口恢复前台时立即更新，保持与底部运行时长各自的含义；项目手工顺序、置顶、折叠和优先级档位沿用既有规则。

侧栏项目、“对话”和项目内 CLI 分组的折叠选择保存到 `state.json` 的 `collapsedSidebarGroups`，切换任务、隐藏侧栏或重启应用后恢复。按分组稳定路径键记忆，排序与置顶保持原选择，新项目默认展开；搜索临时展开匹配结果，清除搜索后回到用户保存的状态。全部展开清除当前项目及其 CLI 子组的折叠记录，保留当前列表外项目的选择。

设置主题与显示语言共用胶囊下拉，对照 `AppearanceSection.tsx` 的 `FamilyDropdown`：36px 高、320px 宽、14px 箭头，弹层 12px 圆角、8px 内距、36px 选项行。二选一的布尔设置使用切换开关。Agent 分区对照 `settingsRowClasses.ts`、`McpServersSection.tsx` 的设置行，按名称、说明、来源排布，只读展示 MCP 与 Skills。

输入历史浏览对照 Cindy `ChatInput.tsx` 与 `composerHistoryProjection.ts`：正文为空或只有空白、且没有附件时，按无修饰的 ↑ 从当前任务最近一条非空用户文字进入，继续 ↑ 浏览更早输入，↓ 返回更新输入，再按 ↓ 恢复进入前的原草稿（保留空格与换行）。历史保留重复输入及已接收插话；浏览期间固定历史快照，新消息到达后在下次进入时采用。连续按住方向键可继续浏览；最早边界和未浏览时的 ↓ 沿用原生光标行为。每次取回把光标放到末尾，由用户编辑或发送。修改正文、加删附件、进入队列编辑、填充其他草稿、发送和切任务均结束当次浏览；已有非空文字、附件、队列编辑、修饰键及输入法处理期间沿用正常键盘行为。新任务历史读完前只使用该任务的实时输入，保持任务隔离。图片或文件的历史引用保持只读，取回文字时不复用已消费的附件 ID。

输入框的未发送文字和附件按任务（新建页一份）保存在内存里，切到设置或别的任务再回来仍在，发送成功后清除。编辑待发送消息使用独立的文字和附件草稿，支持选择、粘贴、拖入与移除图片和文件；保存期间保留并禁用操作，取消编辑恢复普通草稿。

生成速度卡片对照 `RunningTokenRatePopover.tsx`：“最近测得速度”使用最近一次已用真实 usage 校准的请求；工具执行、等待或读数过期时用浅灰显示上一次的速度并注明“暂未生成”，没有有效采样时显示“—”。Rust 用单调时钟从首个输出块计时，生成期间的长间隔继续累计，工具和确认等待暂停。首包 300ms 内的积压、整批工具参数、未流出的 reasoning 不制造速率；流式片段长度只用于分配该次真实输出用量，未作为独立 token 总量。有效采样至少持续 1 秒且含 5 个校准 token。平均按有效片段的总校准 token / 总生成时长计算，峰值为有效请求的最大测得速度，累计输出独立显示 CLI 的全部真实用量。页面只保存主机快照与曲线，渲染和事件到达间隔不参与计速。“按真实用量与生成时长计算”的说明放在卡片底部，不用悬停提示，以免盖住峰值。卡片只在悬停或键盘聚焦时显示，点击不会固定。算法参照 `calibrated-token-speed.ts` 的首包排除、真实用量校准与 `runningTokenRateHistory.ts` 的成对采样原则，当前展示请求结束后校准的读数。
