# 架构不变量

> **状态**：权威
> **读取时机**：改模块依赖、数据流或进程结构之前

## 1. 进程结构

```
页面（React，WKWebView）
  ↕ Tauri 命令和 Channel
Rust 后端（读会话文件、管理子进程）
  ↕ stdin/stdout
用户自己安装的 CLI（每轮一个进程）
```

## 2. 任务数据以 CLI 为准

- 原生会话文件是任务内容的唯一来源，见 [原生会话](native-sessions.md)。
- 一轮结束后，页面丢弃实时内容，重新从文件读取。实时显示和历史显示因此不会长期不一致。
- 生成标题通过 CLI 的原生改名接口保存元数据，消息保持原样。生成请求使用独立的临时任务，见 [生成标题](native-sessions.md#生成标题)。

**不双写。** 已发送的任务内容只从原生格式读取，Tandem 不维护另一份历史。

本地只能存可以丢弃的数据：

- 界面状态，比如置顶和别名；
- 可以随时从原生文件重建的索引，比如以后的全文搜索。
- 尚未发送的消息队列：属于 Tandem 自己的可丢弃草稿，包含附件和入队时的模型、强度、权限选项。发送前只写 `~/.tandem/queues/`，发送时才交给 CLI。

判断标准：删掉 Tandem 的数据目录后，任务内容不能有任何损失。

消息队列由 Rust 后端按任务管理，通过命令增删、编辑、排序、暂停和恢复。正常一轮的进程退出后再取下一条，Agent 等待后台任务而空闲时，队首消息直接转交给这个进程；用户停止、任务出错和应用重启后暂停；任务空闲时新发的消息不受暂停影响，直接发出。拖动锁住整个队列，编辑只锁住正在编辑的那一条。手机端协议的操作名单保持独立。运行中的插话不经过队列，由运行器交给 CLI 的同轮接口；拒收时才进入队列。

领取条目先以 `inFlight` 落盘，CLI 确认接收后才删除该记录。`Started` 表示本轮生命周期开始，接收确认使用各 CLI 的协议回执。重启时将发送中条目放回队首并暂停，由用户确认是否重发。单个队列文件读取或解析失败时独立隔离为 `.corrupt`，通过 `queue-error` 提示，健康队列继续加载和发送。空队列开始新一轮时清除历史暂停和错误并落盘。

队列 JSON 保存正文、次序、状态和图片引用，图片字节独立保存在 `~/.tandem/queues/images/`，编辑和排序沿用已有图片文件。队列与发送中记录都为空时删除 JSON；接收确认后回收对应图片。损坏队列的图片保持保留。

“仍要发送”只授权当次立即发送尝试。该选择属于内存中的临时授权，队列文件和后续排队消息只保存模型、强度与权限模式。恢复、重启及发送前失败后的重试重新检查原生写入者。

配置和界面状态由 Rust 管理，分别写入 `~/.tandem/config.toml` 和 `state.json`。页面只保留内存快照。窗口创建时注入配置，后续通过事件同步；手机任务视图直接读取后端配置与状态。单实例写锁、原子保存和状态损坏隔离见[凭证与本地存储](credentials-and-local-storage.md)。

## 3. 每轮一个进程

一轮开始时启动 CLI，结束后退出。两轮之间 Tandem 不占用任务，用户随时可以在终端续接。

例外是 Claude 的后台任务（后台命令、监控）。CLI 用 `background_tasks_changed` 报告仍在运行的任务；这时发出的结果只表示 Agent 暂时空闲，进程会等后台任务完成，再自己开始下一轮汇报。Tandem 把这段时间算作同一轮：界面显示“后台任务运行中”，停止会连同后台任务一起结束；输入保持打开，新消息直接交给这个进程，排队的消息依次转交。后台任务清空后 Tandem 关闭输入，CLI 完成最后一轮汇报后退出，这一轮才结束。

## 4. 启动路径保持轻量

- 窗口在首次渲染后立即显示，任务列表异步填充。
- Markdown、代码高亮和对话区按需加载。
- 首屏不做更新网络请求，不等待 CLI。自动更新默认关闭；用户启用后由 Rust 在启动 30 秒后按配置检查并下载，调度独立于设置页和窗口可见性。
- 任务列表加载完成后，后台读取一次登录 shell 环境，再启动短暂的 CLI 进程读取模型列表、套餐用量和 Codex 任务列表：`claude -p --no-session-persistence`、`codex app-server` 和 `pi --mode rpc --no-session`。这些读取不创建会话，失败只影响对应的显示；在设置中隐藏的 CLI 不读取任务列表。

## 5. 目录边界

- `desktop/`、`pwa/`、`relay/`、`site/` 互相独立构建。`pwa/` 可以引用 `desktop/design/tokens/`，其他跨目录依赖要先在决策记录里说明。
