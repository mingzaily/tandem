# 凭证与本地存储

> **状态**：权威
> **读取时机**：处理凭证、写文件或新增持久化数据之前

## 凭证

- 用户凭证、令牌、私钥和 CLI 登录文件不进入仓库、日志和测试数据。
- Tandem 不读取、不保存 CLI 的登录凭证，登录态由 CLI 自己管理。

## 用户的文件

- 不写用户的 CLI 配置文件，清单见 [核心产品原则](../product-rules/core-product-principles.md)。
- 会话文件只读，只有 CLI 自己能写。
- 用户生成的标题交给 CLI 改名接口保存为原生元数据；Tandem 继续只读会话文件。

## Tandem 自己的数据

- 原生任务内容仍归 CLI。`conversations/` 是用户工作目录，里面的产物按用户文件保存；`cache/` 只放可重建内容。
- Tandem 自己的文件统一放在 `~/.tandem/`，目录权限 `0700`。三个 CLI 的配置、凭证和原生会话仍在各 CLI 的目录中。

```text
~/.tandem/
├── config.toml       # 用户配置，可手改，Rust 管理
├── state.json        # 置顶、归档、别名、项目顺序和侧栏状态
├── remote.json       # 手机配对资料和私钥
├── .gitignore        # 排除 remote.json、cache/、锁和写入临时文件
├── queues/           # 尚未发送的消息和附件
├── conversations/    # 无项目任务的工作目录
└── cache/            # 按需创建，只放可重建内容；当前没有磁盘缓存
```

`.storage.lock` 是运行期间的独占文件锁，文件可保留，锁随进程退出释放。WebKit 自己的运行数据仍由系统管理在 Library，Tandem 的正常配置读写使用 Rust 存储。

`config.toml` 使用蛇形字段名；主题、语言、字体、发送方式、通知、项目路径、对话目录、默认 CLI，以及三个 CLI 的模型、强度、权限选择都存于此。这些是 Tandem 的发送选项，通过启动参数交给 CLI。模型与强度留空表示跟随 CLI。Rust 用 `toml_edit` 逐字段修改，保留用户注释和字段次序。保存前重新读取当前文件，保留观察间隔内的其他手动修改。`config.toml` 和 `state.json` 都以权限 `0600` 的同目录临时文件写完、同步、原子替换，再同步目录。

窗口创建时用 initialization script 注入有效配置快照，主窗口和独立菜单栏面板都在首次绘制前应用主题。Rust 每 750ms 检查小型配置文件的内容，手改成功后广播快照；错误的语法或字段值留在原文件中，继续使用进程内上次的有效配置并显示错误。设置页也会拒绝覆盖这一份错误文件，修正后自动恢复。语言和其他设置随快照立即应用。主窗口只补充系统显示语言这个运行时观察值，供“跟随系统”的手机确认文案使用。

手机访问的配置在 `~/.tandem/remote.json`（`remote/store.rs`），含桌面端的签名私钥、部署令牌和已配对手机的公钥。权限 `0600`，整份原子写入；根目录自动生成 `.gitignore` 排除它和临时副本。**含私钥，请保持本机存放，不同步到网盘或 dotfiles。丢失后重新配对即可，无需备份。**删除后要重新配对，不丢任务。任务内容不存在这里。

待发送队列在 `queues/<任务 UUID>.json`（`queue.rs`），文件权限 `0600`，目录权限 `0700`，用临时文件写完并同步后原子替换。每条保存消息、附件和入队时的模型、强度、权限模式；“仍要发送”的写入者放行只在内存中作用于当次尝试。普通文件保留由系统选择器或窗口拖入得到的路径。成功落盘后才释放草稿附件的内存 ID。领取时保存为同一文件的 `inFlight`，CLI 确认接收后清除；已接收的历史以 CLI 为准。

图片字节保存在 `queues/images/<任务 UUID>/<附件 UUID>`，文件 `0600`、目录 `0700`。JSON 保存图片引用，编辑、排序和状态变化只重写小型元数据；页面通过受限的 `queue-image:` 协议按需读取预览。发送前在阻塞线程读取当前条目的图片。队列 JSON 只接受图片文件引用。

当前发送条目的气泡预览与 CLI 内容由同一次图片读取生成，气泡使用独立 data URL，接收确认后的文件回收保持气泡可读。待发送列表继续使用文件 URL。

待发送列表与 `inFlight` 都为空时删除队列 JSON。图片在消息被删除或确认接收后回收；启动时清理中断写入留下的未引用图片。带 `.corrupt` 的任务保留对应图片目录，用户清理损坏文件并重启后再回收未引用图片。

重启后待发送消息保持暂停，残留发送中条目恢复到队首并提示接收结果未知，用户核对后决定是否重发。用户点“继续发送”后按保存的顺序发送。单个坏文件保留为 `<任务 UUID>.json.<唯一后缀>.corrupt`，跳过该文件并提示用户，其他队列继续可用。隔离失败时保留原文件和错误提示。删除队列会丢弃其中的草稿；`.corrupt` 也可能包含正文和附件，按本地草稿管理。

## 测试和临时文件

- 测试用 `tempfile` 创建目录，不写用户目录和仓库。
- 日志不记录任务内容。

## 页面状态与单实例

页面只保存内存状态（`lib/storage.ts`、`lib/preferences.ts`、`lib/settings.ts`），所有正常读写都通过后端。模型清单、用量、上下文窗口和安装状态可以重新查询，当前只在内存缓存。`cache/` 中的内容必须能完全重建，删除后保持用户配置、配对、草稿和任务完整。

首次启动立即创建 `config.toml` 和 `.gitignore`。配置快照在创建主窗口和菜单栏面板时注入，首屏前应用主题。状态文件按需写入，缺失时直接采用默认值，队列保持独立。

`state.json` 属于可丢弃的界面状态。读取或解析失败时，持有写锁的实例将原路径改名为 `state.json.<UUID>.corrupt`，使用默认值并通过 `errors` 提示路径；改名失败时保留原路径和原因，拒绝覆盖原文件的状态保存。发送和队列加载继续工作。状态和任务元数据忽略未知字段，已结束使用的旧字段在下次保存时自然移除。

`config.toml` 中的未知字段保留在文件里、忽略其值，并在 `errors` 中列出完整字段名；已知字段继续生效。语法、类型和已知值的校验错误仍保留原文件并沿用进程内上次有效配置，设置页拒绝覆盖错误文件。

`.storage.lock` 的进程级独占锁保护 Tandem 数据。第二个实例可读取配置和状态，但会明确提示另一个实例占用，禁止设置、队列、配对和发送等写操作，也不会改名状态文件。退出另一个实例后，重新打开被阻止的实例。手机任务列表的项目、别名和归档直接来自后端配置与状态。

## 侧栏偏好

`config.toml` 的 `sidebar_group_by_cli` 保存项目内 CLI 分组开关，`sidebar_sort` 使用 `time`、`type` 或 `priority`。`state.json` 的 `pinnedProjects` 保存置顶项目，`unreadTasks` 保存完成未读的任务（新的在前，最多 200 个，打开任务即移除）；任务置顶继续使用 `taskMeta.pins`，项目手工顺序继续使用 `projectOrder`。工作组展开记忆只保留在应用内存。

CLI 配置清单按 [Agent 配置清单](agent-configuration-inventory.md) 只读提取 MCP 与技能元数据，原文件保持原样。
