# 工程规范

> **状态**：权威
> **读取时机**：写前端或 Rust 代码和测试之前

## 通用

- diff 只包含任务需要的行，不顺手重构、不格式化无关代码。
- 不留死代码、占位实现和注释掉的代码。
- 注释说明为什么，不复述代码做了什么。

## 错误处理

- 能预期的失败（文件不存在、CLI 没装、任务 id 非法）用 `Result<T, String>` 返回，由页面显示。
- 错误文案要说清什么失败了。原因明确时给对应的办法，不默认写“请重试”。
- Rust 代码不用 `unwrap` 处理运行时数据。`expect` 只用于启动时不可能失败的情况，测试不受限。
- 单行解析失败要跳过而不是让整个任务打不开，CLI 被打断时可能留下半行。

## 测试

- 业务逻辑默认带测试，纯函数优先：解析放在 `sessions.rs`、`runner.rs`，界面规则放在 `lib/`。
- 测试用自己构造的数据，不读用户真实的任务文件。
- 测试断言行为，不断言实现细节。新增测试要能抓住一个真实的错误。
- 修 bug 时先写能复现的测试。不要为了通过而改弱断言。

## 前端

- 页面只通过 `lib/api.ts` 调用后端。
- 重模块按需加载。首屏不能依赖 Markdown 和代码高亮，改动后看 `vite build` 的入口体积。
- 长列表必须虚拟化。展开状态放在列表外面，因为行滚出视口会被卸载。
- 文案写进 `lib/i18n.ts`，`zh-CN` 和 `en` 同时写。
- 处理 Enter 发送时要判断 `isComposing`，否则中文输入法确认候选词会把消息发出去。
- 图标按钮要有 `aria-label`，所有可操作元素要有可见的键盘焦点样式。

## Rust

- 会阻塞的文件操作放进 `spawn_blocking`。
- 提交前 `cargo test` 通过，没有新增警告。
