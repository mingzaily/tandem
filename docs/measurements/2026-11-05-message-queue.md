# 消息队列验收（2026-11-05）

macOS arm64。全程通过 `TANDEM_DRIVE_SCRIPT` 操作页面，使用 `ZDOTDIR` 注入 Claude、Codex、Pi 替身。工作目录、CLI 数据目录、队列目录均为临时目录；通知关闭。截图只读取 Tandem 目标窗口，浅色和深色都已检查。

## 实现和审查

- Rust 按任务保存待发送消息，图片字节、附件文件路径和入队时的模型、强度、权限随条目保存。草稿附件成功入队后释放内存 ID。
- 一轮的 CLI 进程退出后才自动发送下一条。停止、出错和重启后暂停，点“继续发送”恢复。启动失败、原生任务被别的进程占用等发送前错误保留队首。
- 面板按 Cindy 的几何和 token 实现，4 条以内全显，5 条起显示前 3 条；支持展开、指针拖动、键盘排序、共享输入框编辑、删除。拖动锁住队列，编辑只锁住当前行。长确认卡片和队列共用可滚动的底部区域。
- 菜单栏任务显示排队数。后端命令提供列表、入队、编辑、删除、排序、继续和交互锁；停止任务同时暂停队列。手机端协议保持原样。
- 业务逻辑审查：检查发送边界、暂停恢复、并发领取、附件所有权、原生任务隔离和选项快照；修正连续“停止→继续→停止”时旧恢复请求影响新停止的问题。
- 代码设计审查：检查后台调度与页面职责、错误传播、指针监听清理、异步历史重读和按需加载；直接发送沿用附件所有权转移，避免额外复制图片。

## 启动和内存抽样

同机、替身 CLI、临时项目、新建页。基线为本次修改前的 release 二进制，新版为本次 release。各启动 3 次，第 3 次在窗口显示后 2 秒采样 `footprint --noCategories --format bytes`，统计主进程和同次启动新建的 WebContent、GPU、Networking 进程。

| 指标 | 基线 | 新版 |
|---|---:|---:|
| 首屏显示，3 次 | 819 / 459 / 525 ms | 512 / 390 / 389 ms |
| 主进程物理占用 | 26.6 MiB | 27.4 MiB |
| 主进程与 WebKit 合计 | 90.1 MiB | 91.9 MiB |

抽样总占用增加约 1.8 MiB。首次启动受系统文件缓存影响，启动数字只用于排查明显回退。样本量和任务规模均较小，未覆盖大量排队图片的内存占用。

队列面板独立加载约 9.34 kB JavaScript（gzip 3.24 kB），首屏入口约 405 kB（gzip 123 kB），沿用现有依赖。release 使用 `pnpm tauri build --bundles app` 构建。
