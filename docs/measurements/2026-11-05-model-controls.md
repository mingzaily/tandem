# 2026-11-05：模型与推理档位、输入区弹层

macOS arm64。真实 CLI 元数据验证使用 Claude Code 2.1.318、Codex 0.166.0、Pi 1.5.0。界面几何与交互参考本地 Cindy 的 `components/ui/effort-slider.tsx`、`slider.css` 和推理档位颜色 token。

## 根因与修复

- 待发送队列让输入区成为滚动容器，原来的绝对定位弹层受到裁切。模型列表被裁掉后，页面只剩推理强度滑块。模型、权限、项目、上下文菜单与生成速度卡片改为顶层挂载，按触发器的窗口坐标定位，跟随滚动和窗口大小变化，并按可用空间切换方向。
- Codex 的模型协议解析保留全部 `supportedReasoningEfforts`。本机 GPT-6.1-Sol 返回 `low / medium / high / xhigh / max / ultra` 六档，配置中的默认值为 `max`。补充六档回归测试，并将 `ultra` 中文名称改为“极限”，与“超高”“最高”区分。
- Claude 的模型切换失败后，原实现仍读取上一个模型的设置。现在只在切换成功后查询该模型默认强度，失败时保持默认值未知。初始化失败、错误格式和提前退出向页面返回错误，保留缓存清单。实测 Sonnet 5.5 默认“中”，Opus 5.5 默认“高”，非推理模型隐藏滑块。
- Pi 原实现手工推断档位，遗漏 `off`，还把当前模型的强度当成全部模型的默认值。现在在无会话临时进程中逐个切换模型，读取官方 `get_state` 与 `get_available_thinking_levels`。本机 DeepSeek、GLM、Grok、GPT 与 Claude 的自定义能力映射各自生效。
- 模型菜单增加加载、读取失败、缓存说明、空列表指引与刷新。新任务中三种 Agent 始终各有入口。已选模型暂时不在清单时，触发器显示所选标识。
- 滑块按参考组件还原 38px 操作区、12px 轨道和 21px 滑块。指针松开提交，取消保留原值，方向键、Home、End 可选档；刷新能力清单时取消旧手势。单一档位显示文字。
