# 2026-11-05：生成标题与 Codex 附件显示

macOS arm64。生成流程参考本机安装的 `@agegr/pi-web` 0.15.0：`api/sessions/[id]/auto-name` 提取有界对话，独立请求当前模型，再用 `setSessionName` 保存。Tandem 使用用户安装的三种 CLI，界面参考 Cindy 的 `SessionRenameInput.tsx` 和现有标题栏、任务菜单的 token。

## 实现与审查

- 标题栏和任务菜单提供“生成标题”。模型请求使用临时目录和临时任务，保留对话开头和近期结果，最多 6000 个字符。输出清理格式后限制为 80 个字符。
- Claude、Codex、Pi 分别通过 `rename_session`、`thread/name/set`、`set_session_name` 保存原生标题，聊天消息保持原样。成功后界面采用原生标题；生成期间的手动别名优先。失败时保留原标题并显示错误。
- Claude 和 Pi 的运行中任务复用现有进程保存元数据；空闲时短暂续接，发送元数据请求后退出。元数据写入与队列调度互斥，暂停的队列保持暂停。
- Codex App 的附件封装转换成用户正文、图片和文件标签。按完整结构识别，普通 Markdown 和不完整封装保留原文，多个文本块保持原顺序。
- 业务逻辑审查检查原生保存、消息隔离、手动改名竞争、运行中元数据交互、暂停队列和失败语义，修正生成标题只留本地别名的问题。
- 代码设计审查检查 CLI 适配、临时目录生命周期、请求边界和错误传播。生成模块复用三种 CLI 驱动，权限与原任务隔离，内部临时任务选项由 Rust 设置。修正空队列已暂停时发送按钮仍显示入队文案的问题。
