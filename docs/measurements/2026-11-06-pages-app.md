# 官网交付 PWA 验收

日期：2026-11-06。范围：官网与手机端的静态发布组合、子路径安装和离线缓存。

## 目录与交付

`pwa/`、`site/`、`relay/` 保持仓库顶层，分别构建。`site` 的 `build:pages` 依次构建官网和带 `/tandem/app/` base 的 PWA，再把手机端产物复制到 `site/.vitepress/dist/app/`。默认 PWA 构建继续使用根路径，供中转镜像自托管。

Pages 工作流同时关注官网、PWA、共用设计 token 和发布脚本；发布配置的目标地址为 `https://mingzaily.github.io/tandem/app/`。本轮完成本地实现与验证，保留工作区改动，尚未提交或执行线上发布。中转由使用者自部署，手机从配对码取得 WSS 地址。

官网导航、首页手机访问区和相关文档增加手机端入口。入口执行完整页面跳转，由 PWA 接管自身页面。图标、manifest、安装入口和 worker 跟随构建 base；官网与手机端共享来源的代码信任边界已写入安全说明。

## 两轮审查

业务逻辑审查核对了官网跳转、部署地址、安装身份、根路径自托管、离线打开和缓存隔离。审查发现 manifest 的相对 `id` 会解析到来源根路径；删除显式 `id`，由已解析的 `start_url` 确定安装身份，并通过 Chrome 的 `Page.getAppId` 验证子路径和根路径两种构建。安装范围与 worker scope 均落在对应应用路径。

代码设计审查核对了项目构建边界、发布脚本职责、缓存清理范围和新增依赖。构建阶段集中处理 base；运行时沿用 Vite 的 `BASE_URL`。缓存只保存固定外壳资源，更新仅删除相同部署路径的旧缓存。固定名称的 manifest、HTML 和图标也参与版本计算，避免只更新图标时继续使用旧外壳。本轮复用已有依赖，范围内已知阻塞问题已处理。

## 性能、清理与边界

子路径构建的首屏 JavaScript gzip 为 101.45 kB，改动前为 101.43 kB，增加约 0.02 kB；CSS gzip 为 14.33 kB。新增哈希计算仅在构建时执行，运行时继续使用现有 worker，未增加依赖或轮询。启动耗时和常驻内存未单独复测。

本轮启动的浏览器、中转和测试服务器已退出。测试使用独立浏览器上下文，用户的 `remote.json` 和 localStorage 保持原状。本轮恢复的 PWA／relay 开发依赖、构建产物及临时 Rust target 在验收后清理；原有官网开发服务及其他会话的依赖和缓存保留。

尚未验证 GitHub Actions 的实际执行、线上 Pages 路由、真机安装、iOS 主屏幕存储、相机、软键盘、后台恢复、公网 WSS 或真实桌面端互通。本轮未修改 relay 和桌面端业务代码，relay 的完整单元测试、clippy、集成测试及真实桌面互通沿用前一批记录。
