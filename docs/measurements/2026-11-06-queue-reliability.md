## 实现契约

| 问题 | 当前行为 |
|---|---|
| 坏文件 | 每个文件独立读取与解析。失败文件改名为 `.json.<唯一后缀>.corrupt`，保留原内容并发出 `queue-error`；隔离失败时保留原路径。其余队列正常工作 |
| 错误通知 | 已识别任务 ID 的错误显示在对应任务；未知文件通过 `taskId: null` 显示全局提示。前端先注册变化和错误监听，再读取初始队列 |
| 空队列重新发送 | `reserve` 清除 `paused` 和 `error`，持久化成功后标记任务运行中；本轮期间新入队的消息可正常续发 |
| 领取 | 同一原子写入将队首移到 `inFlight`，保留正文、附件与选项；列表只显示其余待发送条目 |
| 确认接收 | 内部接收回调清除 `inFlight` 并落盘；生命周期事件 `Started` 保留原语义 |
| 发送失败 | 接收确认前失败恢复到队首并暂停；确认后失败只暂停余下队列 |
| 崩溃恢复 | `inFlight` 回到队首，落盘为暂停状态，提示接收结果未知；用户核对后决定重发或删除 |
| 接收确认写入失败 | 内存记住 CLI 已接收，避免当前流程重发；磁盘保留旧证据，重启后按接收结果未知恢复 |
| 恢复写入失败 | 保留有效队列文件与原发送中记录，内存恢复为暂停，报告保存错误；恢复写入能力后可继续保存与发送 |

CLI 接收信号：Claude Code 的 `--replay-user-messages` 主会话回显（`user`、`isReplay: true`）；Codex 的 `turn/start` 成功响应或轮次通知；Pi 的 `prompt` 成功响应。Claude 的本机帮助与回显实现、Pi 的本机 RPC 实现已核对。Codex 的线程启动和续接继续只传 `sandbox: read-only`。
