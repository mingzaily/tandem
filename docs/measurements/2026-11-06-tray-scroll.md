# 2026-11-06：菜单栏长列表滚动边界

面板原先只有 560px 最大高度，页面按内容计算滚动范围。原生窗口变矮时，底栏和列表末尾落到窗口外；滚动条仍按较高的页面计算终点。

## 修复

页面使用实际窗口高度进行 flex 布局，固定标题和底部操作，中间区域承担滚动。内容增加独立的自然高度测量，用于申请原生窗口大小；任务减少后窗口恢复紧凑高度。窗口 resize 后重新判断上下滚动边缘。

改动位于 `desktop/src/components/TrayPanel.tsx`。沿用现有原生窗口尺寸命令、560px 上限、任务数据和刷新流程。

## 两轮审查

- 业务逻辑：检查末条任务可见、滚动终点、底部操作、任务增减、窗口伸缩以及浅深色。
- 代码设计：分开窗口可见高度与内容自然高度，复用既有 flex 容器和滚动边缘计算；保持现有数据通路。

## 验证

修复前在 480px 原生窗口复现：页面和底栏仍到 560px，最后一条任务底边在 505px，均超出可见范围。

修复后通过独立标识的真实 Tauri 调试实例，以页面脚本操作和断言：

| 场景 | 结果 |
|---|---|
| 7 条任务，560 / 480 / 360px 窗口 | 均能完整滚到最后一条，底栏边界与窗口底边一致 |
| 30 条任务，560 / 480 / 360px 窗口 | 均能完整滚到最后一条，内部滚动范围正确 |
| 长列表清空 | 原生窗口和页面均恢复到 196px，无残余滚动位置 |
| 深色 30 条任务，480px 窗口 | 滚动终点、末条任务和底栏边界检查通过 |

回归脚本：[drive.js](assets/tray-scroll/drive.js)；原生窗口与 DOM 断言：[checks.json](assets/tray-scroll/checks.json)。脚本用于独立测试应用，调用现有 `TANDEM_DRIVE_PANEL_SCRIPT` 入口；运行前备份 localStorage，结束后还原并清理测试数据。
