# 2026-11-12 关于页更新与自动检查设置

更新操作统一迁入“设置 → 关于”的版本信息右侧，左下角用户卡片仅显示版本。新增“自动更新”开关和“检查更新间隔”下拉，沿用现有设置行、SettingsButton 和 SettingsSelect。

## 产品行为

- 自动更新默认关闭，检查间隔默认 6 小时，可选 1、6、12、24 小时；关闭时仍可预设间隔，说明为“开启自动更新后生效”。
- 自动更新开启后在后台检查并下载，安装和重启始终等待用户点击。手动检查在自动更新开启时也会自动下载发现的新版。
- 首次自动检查最早在启动 30 秒后执行，后续以最近检查或下载尝试按所选间隔调度。修改配置重新计算后续计划；失败等待间隔，下载已就绪时暂停后续检查。
- 关闭自动更新停止后续自动请求，已经开始的下载继续完成校验。单实例只读进程不执行自动更新。
- 检查、下载、错误和已验证包由 Rust 在内存中保存。切换设置页或隐藏窗口后保持状态，重新进入关于页读取当前快照；应用退出后清理。
- 任务运行、标题操作和 Agent 安装登录仍阻止安装。失败保留下载包，可以重试，不会自动重启。

## 业务逻辑审查

核对默认值、旧配置省略字段、开关和间隔校验、配置原子保存、手动文件变更、检查与下载失败、已就绪更新、长时间间隔、切页后恢复以及安装任务保护。调度使用单调时间与单个操作锁，状态 revision 避免旧请求覆盖新进度。

签名、版本绑定、下载地址限制及安装保护沿用原更新链路。自动任务只执行检查下载，没有调用安装路径。默认关闭时没有新增更新请求。

## 代码设计审查

Rust 统一持有操作状态、进度和调度，状态查询在下载期间可用；页面只处理快照、事件和用户动作。配置通知复用 storage publish，下载进度按 100ms 节制，只有阶段变化或配置变化唤醒调度。页面卸载会清理事件订阅，晚注册的订阅也会释放。

新增 `auto_update` 与 `update_check_interval_hours` 字段，前后端配置映射、TOML 模板、持久化与手改规则一致。移除原侧栏按钮、浮层和前端更新状态控制器，关于页复用现有按钮及设置组件；没有新增依赖、CSP 或页面插件权限。
