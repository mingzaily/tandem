# 2026-11-12 调试日志

“设置 → 关于”新增“诊断”分组：调试日志开关、日志文件夹入口和清除按钮。日志只写在本机 `~/.tandem/logs/`，用户反馈问题时自己附上文件。规则见[凭证与本地存储](../dev-rules/credentials-and-local-storage.md#诊断日志)。

## 产品行为

- 开关默认关闭，存为 `config.toml` 的 `debug_log`，界面保存和手改共用现有配置链路，切换立即生效。
- 错误和启动行始终记录，问题发生在打开开关之前也能留下线索。打开后另外记录每轮的发送参数、CLI 启动与退出、登录 shell 的 PATH 和跳过的输出行。
- 不记录提示词、回复、附件内容和参数值；家目录显示为 `~`。按天分文件，保留 7 天，单日 10 MB 封顶，单条 4000 字节截断。
- 只有持有数据锁的实例写日志。界面的“打开文件夹”和“清除”只作用于固定目录，页面不能传路径。

## 实现

- `diagnostics.rs`：独立写入线程持有文件，调用方只发消息，异步任务和界面线程不做文件写入。没有新增依赖，本地时间用 `localtime_r`，系统版本用 `sysctlbyname`。
- 埋点：`queue::dispatch`（所有发送共用的入口，含手机和队列）、Claude/Codex/Pi 启动与退出、登录 shell 环境、配置拒绝与保存失败、更新失败、中转连接、菜单栏和角标。原来正式版看不到的 `eprintln!` 改为写日志。
- 命令：`open_log_folder`、`clear_logs`、`log_page_error`。页面的未捕获错误和未处理的 Promise 拒绝通过最后一个命令记录，正文受单条截断和单日上限约束。
- `.gitignore` 增加 `/logs/`。

- `pnpm typecheck`：通过。
- `pnpm test`：55 个文件、343 项通过（设置往返测试覆盖 `debug_log`）。
- `cargo test`：284 项通过，1 项原有忽略。新增日志文件权限与格式、截断与单日上限、过期清理与清除、参数值过滤、配置默认值与手改校验测试。
- `cargo clippy --all-targets -- -D warnings`：通过。
- `pnpm build`：主入口 JS gzip 150.35 kB。没有新增前端依赖，未复测启动和内存。

## 替身验收

使用独立标识的调试包 `Tandem Log Audit`，`TANDEM_DRIVE_DATA_DIR`、`ZDOTDIR` 和三个 CLI 的配置目录都指向临时目录，Claude 使用替身脚本。页面通过 `TANDEM_DRIVE_SCRIPT` 操作 DOM，发送通过后端 `send_turn` 命令。

| 步骤 | 结果 |
|---|---|
| 开关关闭时发送失败的一轮 | 只有头部、启动行和一条 `ERROR turn` 失败原因，没有 DEBUG 行 |
| 在关于页点击开关 | `aria-checked` 由 false 变 true，`config.toml` 写入 `debug_log = true`，日志记录 `debug logging on` |
| 开关打开时发送成功的一轮 | 记录工作目录、默认选项、CLI 路径与参数名、进程号、跳过的非 JSON 行、退出状态 3 与 stderr、结束状态 |
| 页面错误 | 未捕获异常和未处理的拒绝都写入 `page:main`；修正后拒绝也保留错误消息（WebKit 的 stack 不含消息） |
| 提示词检查 | 三次发送的提示词标记在日志中出现 0 次 |
| 浅色/深色 | 卡片、标题、说明文字跟随主题 token；两个按钮在卡片内，页面无横向溢出 |
| 清除 | 日志文件删除，显示“日志已清除。”，下一条记录重新带头部 |
| 重启 | 开关保持打开，启动后即记录登录 shell 的 PATH |
| 第二个实例 | 同一数据目录再开一个实例，日志行数不变，没有第二条启动行 |

本次会话没有屏幕录制权限，窗口截图失败，界面以 DOM 和计算样式断言为证，没有保存图片。“打开文件夹”沿用已有的系统 `open` 调用，未在验收中点击，避免在用户屏幕上弹出访达窗口。

测试目录、替身、调试包和该标识的 WebKit 数据已删除。四份用户 CLI 配置的 SHA-256 与本批开始时一致。没有提交或推送。

## 观察

日志显示登录 shell 环境在启动后约 0.5 秒就被读取，早于第一次发送。架构不变量写的是“第一次发送时才读取”，这是本批之前就有的行为，读取方尚未确认，留给后续核对。
