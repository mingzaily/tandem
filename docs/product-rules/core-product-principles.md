# 核心产品原则

> **状态**：权威
> **读取时机**：新增或调整功能、判断一个能力该不该做之前

## 1. 目的

让用户在一个界面里用好自己已经安装的 Claude Code、Codex 和 Pi，并且比 Electron 客户端占用更少内存、启动更快。Tandem 面向个人工作流，macOS 安装包由 CI 构建并发布到 GitHub Releases，用户下载后安装。“设置 → 关于”提供检查更新、下载校验和安装重启。自动更新默认关闭；用户开启后按所选间隔检查并下载，安装和重启始终由用户确认。左下角版本仅作展示。

## 2. 不变量

| 原则 | 要求 | 怎么验证 |
|---|---|---|
| 用用户环境里的 CLI | 从登录 shell 的 PATH 和用户的登录态获取。不内置、不托管、不自动更新。用户点“安装”时才用 npm 全局安装，点“登录”时运行 CLI 自己的登录 | 安装和登录只由设置页的按钮触发，包名是固定名单 |
| 不改用户的 CLI 配置 | 不写 `~/.claude/settings.json`、`~/.codex/config.toml`、`~/.pi/agent/*.json`。CLI 自己写的会话和状态除外 | 每批前后比较这些文件的 SHA-256，有变化要说明来源 |
| 不上报 | 没有遥测和崩溃上报，不连接 Cindy 服务端；手动检查或用户启用的定期检查访问 Tandem 的 GitHub Releases，下载校验成功并由用户选择后安装重启 | CSP 限制页面网络；审查新增的网络调用 |
| 不需要登录 | 本机功能不需要账号 | 没有登录流程 |
| 随时可以不用 Tandem | 任务留在各 CLI 里，可以从终端续接。删掉 Tandem 的数据目录不丢任务 | 在终端 `claude --resume` 能继续 Tandem 跑过的任务 |
| 轻量 | 启动和内存是产品指标，不是优化项 | 重要改动后按 [实测方法](../performance.md) 复测 |

## 3. 判断要不要做一个功能

- 用户离开 Tandem 时会丢东西的功能，默认不做。
- 常驻后台、拖慢启动的功能，要改成按需加载，否则不做。
- 需要 Cindy 账号或 Cindy 服务端的功能不做。

## 4. 界面

界面尽量复刻 Cindy，规则见 [设计规则](../design-rules/README.md)。Cindy 的名称、Logo 和角色形象不在 Apache-2.0 许可范围内，不复刻。
