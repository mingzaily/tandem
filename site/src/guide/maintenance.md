# 升级与排错

## 升级

`latest` 跟随中转的最新发布。固定版本时，将 `compose.yaml` 中的镜像标签换为已发布的 `relay-v<版本号>`，例如镜像地址格式为 `ghcr.io/mingzaily/tandem-relay:relay-v<版本号>`。

```sh
docker compose pull
docker compose up -d
docker compose exec relay /tandem-relay healthcheck
```

保留 `/data` 命名卷。升级前可停服务并备份该卷，备份包含设备准入信息，请按敏感数据保管。更换服务器时，将数据卷一同迁移；同一份数据由一个中转实例使用。

官网手机端随官网更新；中转镜像内附的手机端随镜像升级。手机关闭全部 Tandem 页面后重新打开，以加载新版界面。离线时可以打开应用界面，查看任务需要电脑在线。

## 健康检查失败

运行 `docker compose ps`、`docker compose logs relay`。确认部署令牌已设置、端口可用、数据卷可写。容器内部检查命令是 `/tandem-relay healthcheck`，无需安装 curl。

`PERSIST_FAILED` 表示设备准入信息写入失败。检查磁盘空间和 `/data` 权限；绑定目录的 UID/GID 应为 `65532:65532`。修复后，等待桌面端重新连接，再生成配对码。

准入文件 `tokens.json` 损坏或读取失败时，启动日志会显示实际路径和恢复办法。先停止中转，检查 `TANDEM_RELAY_DATA_FILE`、文件类型和权限；路径应指向可读写的文件。修正路径或权限后重启即可。

需要重建准入文件时，将日志中的原路径改名保留（例如 `tokens.json.corrupt`），然后重启中转。默认容器路径为 `/data/tokens.json`，在挂载的数据卷中操作。原文件也可以从敏感数据备份恢复。桌面端重连时先重新登记全部已配对设备的令牌哈希，收到持久化确认后校准列表；原手机继续使用配对身份和令牌，无需重新配对；如果手机在桌面端重连前已被中转拒绝，桌面端恢复后重新打开手机端页面。保持桌面端部署令牌与中转一致，并保留电脑上的 `~/.tandem/remote.json`；这份私钥文件仅在本机保存，不同步到网盘或 dotfiles。

## 手机无法连接

确认页面是 HTTPS，中转地址是带 `/ws` 的 WSS，证书被手机信任。`ws://` 只用于本机开发；通过手机局域网 IP 访问普通 HTTP 无法使用 WebCrypto。

如果间隔固定时间就断线，检查代理是否转发 WebSocket 升级头，读超时是否大于 90 秒。大量准入失败后，同 IP 会在一分钟窗口内受限；检查地址、令牌及代理来源地址配置后，等待窗口结束。

## 已配对却找不到设备

iOS 的 Safari 与主屏幕 PWA 存储独立。请从主屏幕打开并在其中配对；清除网站数据、换浏览器或换域名后也需要重新配对。

配对码过期或使用过时，在电脑重新生成。配对期限为五分钟，电脑等待中转确认后展示配对码；期限使用相对时长计算。配对时出现 `4400`，检查桌面端与中转是否都已升级到当前版本。手机与电脑都显示六位确认码后，在电脑允许。

## 桌面端离线或任务在别处运行

保持电脑联网，运行 Tandem 并启用远程功能。电脑重新上线后手机会重新握手。任务在终端或其他窗口运行时，等它完成再发送。

操作期间断线而显示“结果未知”时，先重连并查看任务状态，再决定下一步。服务不会自动重放可能产生写入的请求。

## 撤销与关闭码

`4411` 表示电脑断开了本次会话，手机保留配对身份并自动重连。`4429` 表示连接或准入失败次数受限，也会自动重试。重试从 1.5 秒开始翻倍，最大间隔 30 秒，握手成功后恢复初始间隔。

`4410` 表示电脑尚未配对此手机，或已撤销手机。手机会清除本机配对身份、停止重连并提示重新配对。`4400` 为协议版本或帧格式错误，`4401` 为准入失败或超时；手机停止重试，检查版本、地址和配对信息后再连接。`4409` 表示同房间的桌面端被新连接替换。`1009` 表示消息超过硬上限，`1013` 表示接收方积压。

配对阶段是单次尝试：连接提前关闭时按提示重新配对；已收到并验证最终配对回复时，后续连接关闭保留配对结果。
